# Playback engine: performance policy and limits

`scorestream_app::playback::plan_source` validates the current SFS source and returns a deterministic, device-independent `PlaybackPlan`. It does not mutate workspace history, use a last-good snapshot for an invalid draft, open an audio device, or request MIDI access. The desktop transport consumes this plan through the asynchronous native `playback_plan` command. Built-in Web Audio synthesis schedules its notes against the audio clock.

## Implemented interpretation

- Exact rational tempo integration, quarter-note score units, all registered ordinary and dotted beat units, positive rational BPM, and tempo changes inside held notes. Default without tempo state is quarter = 120. Floating-point conversion happens only at the output boundary; there is no per-note cumulative clock drift.
- Multiple parts and voices, stable part/instrument routes, frame-wide instrument changes, chromatic/octave transposition with staff override, and fractional pitches in the built-in frequency contract. Written durations, dots and tuplets are not multiplied twice: measured event duration is authoritative. Printed metronome marks do not override tempo state.
- Persistent dynamics use score → part → staff → voice specificity. Event dynamics affect only that event. The velocity policy is pppp 16, ppp 24, pp 36, p 48, mp 64, mf 80, f 96, ff 112, fff 120, ffff 127. Scope sfz accents attacks at its timestamp and preserves the previous sustained level; scope fp establishes p after its forte attack. Event sfz returns to its scoped level and fp decays to p over at most 80 ms. These are documented performance choices, not additions to the normative score model.
- Explicit crescendo/diminuendo relations interpolate velocity in musical time for the starting voice. Target is an explicit endpoint event/scoped dynamic; absent a target, a reported policy uses ±24 velocity steps. Sustained notes receive a gain envelope, not merely different velocities on later note attacks. Tempo boundaries preserve beat-linear ramps in seconds. An intervening same-scope dynamic terminates the remainder of a ramp; wider-scope changes remain available as current fallback. Hairpins are half-open, bounded intervals. At their terminal anchor the current underlying dynamic resumes unless an explicit dynamic establishes a new value. Later same-scope dynamics terminate the curve; narrower event-local assignments shadow it without multiplying it.
- Ordinary gate 92%, staccato 50%, staccatissimo 25%, tenuto 100%, breath mark 80%, accent +16 and strong accent +24 with clamping. Shorter conflicting gates win. Same-voice slurs make ordinary gates legato through the penultimate note. Articulation is a policy approximation, not sample-library keyswitches.
- Sounding tie chains produce one attack through contiguous tails; print-only ties do not merge. Instrument-route changes and branching ties are refused. Final articulation determines the final tail; intermediate tied attacks/marks do not retrigger the sound.
- Pedal relations sustain all voices of the starting part until lift, including continue anchors that lift/re-depress the pedal. Overlapping intervals merge. Partial values use a reported 0.5 threshold, not a half-pedal acoustic model. Sustain here is release-time extension; an external renderer need not send MIDI CC64 to reproduce this duration policy.
- Explicit `octave sound=true` shifts the starting voice through the final endpoint's duration. Core validation still rejects sounding ties combined with sounding octave relations; the engine does not bypass validation.

## Explicit limits

Legacy grace notes without the fidelity capability, cue notes and unmapped unpitched identities are silent with warnings. Imported `scorestream.grace@1` notes reject ordinary playback; a separate [explicit following-principal API](GRACE_PLAYBACK.md) realizes supported groups without changing that default. The registered navigation capability uses the [bounded performed projection](SFS_NAVIGATION.md) for ordinary closed repeats and endings, with exact state checkpoints and distinct occurrence identities. Unsupported open/complex navigation, cross-jump ties, symbolic expression spans and unresolved fermata holds reject; no navigation is invented from words. Words, lyrics, harmony and other printed marks are not performance commands. Ambiguous cross-voice hairpins/slurs/octaves and cross-part pedal spans are reported and omitted; overlapping hairpins are refused. Pitches outside MIDI 0–127 are omitted with a warning. Limits are 4 MiB input, 100,000 events and six hours of interpreted time. Very short notes below a microsecond are refused.

The JSON contract contains duration in seconds; ordered notes (event identity, route, onset, duration, MIDI pitch, frequency, initial velocity 1–127, relative gain-envelope points); unique sorted routes; and deduplicated warnings. A gain of 1 is relative to the initial velocity, not maximum amplitude. No global master gain or chosen output device is stored in the score.

## Fixture and verification

Use `examples/playback-expressive.sfs` to exercise the performance plan. The current engraver rejects mid-score state changes, so this fixture may retain the previous notation; use First Light or a constant-tempo fixture for cursor/follow/seek checks. Its two parts are piano and violin. Quarter = 120 runs for four beats, then dotted-quarter = 60. Expected total duration is 5⅓ seconds, 11 sounding note attacks and two routes. Listen for the held violin swell and fade, the piano's pedal-release boundary at two seconds, one unbroken tied high C, short staccatissimo B, and fp decay. This fixture is a manual listening guide, not a claim of hardware verification.

Rust tests assert exact tempi, tie continuity, scope priority, articulations, held-note envelopes, pedal lift, fp, frame-wide changes, transposition/microtones, deterministic routes, invalid-input refusal, finite clock values, and 10,000 events without accumulated timing drift. Tests use no audio/MIDI devices. The performance assertion is a generous debug regression threshold, not a latency guarantee. Existing dependencies and lockfiles are unchanged.

Output adapters must schedule against their audio clock, cancel future events and silence active notes on stop/pause/errors, guard stale asynchronous play attempts, and expose routing failures. The [Web Audio specification](https://www.w3.org/TR/webaudio/) provides the built-in clock/envelope API. [Web MIDI](https://www.w3.org/TR/webmidi/) is an optional capability, not evidence of support in macOS WKWebView or Linux WebKitGTK. Native CoreMIDI/ALSA/Windows MIDI output is a separate follow-up requiring a native adapter and platform validation. Built-in synthesized timbres are not a sampled orchestra or SoundFont engine.

## Typed-model migration

The playback compiler now consumes `scorestream_core::notation::ResolvedScore`, not wire attribute maps. SFS lowering, exact expression intervals, numeric expression policy, continuity/pedal realization, tempo integration and output DTOs are distinct modules. See [expression interval contract](EXPRESSION_INTERVALS.md) and [implemented model boundaries](SEMANTIC_MODEL.md). The output retains `warnings` and adds structured diagnostics with feature, object/source, effect and policy identity. This internal migration does not change SFS 1.1 syntax or its public AST schema.

## Desktop transport and score position

The plan adds `event_positions` (every written event, including rests, spacers and tied continuations) and `measures` (explicit measure IDs, parts, labels and boundaries). Their seconds come from the same Rust `TempoMap` as sounding notes. Written endpoints remain distinct from articulation and pedal releases. Old serialized plans deserialize with empty timeline arrays.

The React score toolbar uses existing official shadcn Button/Input/Select controls for play, pause, stop, seconds and measure seeking. Space toggles playback outside editors, form controls, menus and dialogs. Clicking a note or rest selects it and seeks to its Rust start time. The cursor interpolates between engraved anchors within each system and follows new systems while playing. It appears only when the source and render sequence match, never on a retained invalid/older preview. Unsupported engraving can still play a valid source, but its retained score cannot seek or show a misleading cursor.

The built-in output now resolves 40 pitched orchestral identities to 25 modest synthesized profiles, with 11 additional unpitched identities cataloged but not rendered as drums. These are not sampled instruments or a SoundFont engine. See [the orchestral catalog, exact aliases, shared profiles and limits](ORCHESTRAL_INSTRUMENTS.md). The original `piano`, `flute` and shared `cello`/`violin`/`strings` signals are preserved. Unknown identifiers, including differently cased names, deterministically use the previous neutral triangle tone. Arbitrary instrument atoms remain valid score data; resolving a catalog identity never changes pitch, transposition or the stored identity.

Every note uses its Rust-provided instrument, so concurrent parts and frame-wide instrument changes route independently rather than inheriting a global or first-part sound. Periodic waves have matched steady-state energy before piano decay; this is a gain calibration, not a perceptual loudness guarantee. The piano's amplitude falls to 0.8 at 80 ms, 0.55 at 600 ms, 0.3 at 2 seconds and 0.12 at 6 seconds, then remains at that level until release. This local timbre envelope is multiplied by, and never replaces, the Rust velocity/expression envelope. A held piano note keeps decaying under sustain; flute and strings sustain the expression level. Seeking samples both envelopes at the original note age instead of restarting the piano's attack.

All parts and voices sound concurrently with Rust frequencies, velocities, held-note envelopes, ties and pedal-adjusted release times. The same short 8 ms attack/12 ms release (bounded to one third of a short note) smooths oscillator boundaries for every profile, with no extension beyond the planned note duration. A 180 ms lookahead schedules audio; a 25 ms transport timer reads the audio clock, not a JS accumulated timeline. Pause/stop/seek/source edits cancel queued and active voices. Seeking into a tied or pedal-held note resumes its remaining duration and envelope without inventing another source attack. Every asynchronous plan/resume request is guarded against stale completion.

### Restoration verification

The restored source was based on GitHub commit `92e22d3582794e487c3b6088626ec983d04a05a4`. Frontend transport/audio tests use mocked clocks and nodes, and UI tests use DOM geometry fixtures. They do not claim native sound-device or platform verification. Rust workspace tests, formatting and native desktop builds must run in a Rust-capable environment; the restoration cloud workspace has no Cargo/Rust toolchain. No runtime capture instrumentation or file-dialog changes were added.

### Timbre verification

The timbre slice is based on the published restoration tree at `c26b4b47658161ca6b311fe13e95832a660d17c9`. Mocked graph regressions cover exact route changes, shared string aliases, deterministic fallback, balanced harmonic coefficients, separate expression/decay gains, truncated decay interpolation, sought note age, short gates and cleanup after waveform construction failure. The independent `npm run test:audio-render` harness runs the same voice graph through a real browser `OfflineAudioContext` and inspects rendered samples for spectra, expression, velocity, simultaneous notes, seeking and silence outside note boundaries. It is test-only and is not imported by the production application.

In the implementation workspace, the frontend suite and production TypeScript/Vite build ran successfully. The offline-render harness was attempted but Chromium could not launch because the workspace forbids its `socket()` call. No sandbox exceptions, new packages or audio-device changes were made. Rendered-signal verification therefore remains pending in a browser-capable environment, as do native output and physical-device listening checks. Cargo/Rust is still unavailable here; this slice changes no Rust files.
