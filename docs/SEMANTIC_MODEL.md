# 通用语义模型：第一阶段已实现范围

本次是可以执行和测试的模型层改造，不是“所有音乐符号已经支持”的声明。SFS 仍是输入语言格式，1.1 文本语法、原有 JSON AST、canonical 输出和格式发现资源均保持不变。

## 实际数据流

SFS 文本 → 原有 codec/验证 → `notation::lower_document` → 类型化 `ResolvedScore` → `resolve_expression` 生效区间 → 分模块播放编译 → 播放计划。

- `scorestream-core/src/notation/model.rs`：声部/声轨/谱表/事件/关系身份、明确作用域、力度等级、复合力度、发音法、方向、事件、关系端点和速度单位。
- `notation/lower.rs`：唯一的 SFS 字段解释边界。先验证，再解析字段、引用、谱表状态、乐器变化和移调，保留来源位置。播放模块不再自己读取 `Attributes` 或判断 SFS 字符串。
- `notation/intervals.rs`：把持续力度变成互斥区间，把 sfz/fp 的起音意图独立建模，确定渐强/渐弱的起止和覆盖，不在这里绑定 MIDI 数值。
- `scorestream-app/src/playback/`：`expression` 负责已声明的数值演奏策略，`continuity` 负责连音/踏板/八度与释放，`tempo` 负责精确时间积分，`plan` 定义输出，`diagnostic` 提供带对象和来源的结果。原 743 行入口已拆成简短编排入口。

## 现在如何决定“哪些力度生效”

同一作用域的持续力度，后者替换前者。作用域优先级为：全谱、声部、谱表、声轨、单个事件，由宽到窄。新的父层力度不能压过仍有效的窄层力度。

局部区间结束后重新查询父层“此刻”的值，不恢复开始时缓存的旧值。渐强是半开区间 `[开始, 终点音符起点)`，不是永远累加的偏移量；同层新力度会提前终止它。更窄的局部力度只在其区间内遮住曲线。相邻曲线不重叠；真正同层重叠或同拍冲突会给出带对象 ID 的错误。

sfz 不再错误地把原有弱奏重置成 mf；它只产生短促强调。fp 表示 forte 起音和目标范围内的 piano 持续部分。多个重音选择最强要求而非任意相加；断奏时值和力度属于不同维度，可以同时生效。具体数值属于标识为 `sfs1.1-expression-v2` 的演奏策略，不冒充所有乐器通用的唯一标准。

内部方向模型支持明确的可选结束位置，以便未来转换器表达有限谱表范围。**SFS 1.1 没有新增这个语法**：现有事件力度止于事件测量尾部，普通 scope 力度止于下一条同层赋值或谱末。内部有限谱表区间也有独立测试，不能因此声称 SFS 已能书写所有此类范围。

## 可复验实例

`examples/expression-scope-study.sfs` 有两条声轨和两个谱表，速度为四分音符 120。它测试谱表弱奏、单音 pp、渐强、强拍上的 accent + staccato、同声轨 mf 终止渐强，以及 sfz 后回到原力度。

用不连接音频设备的命令检查：

    cargo run --offline --locked -p scorestream-app --example inspect_playback -- examples/expression-scope-study.sfs

预期上声轨 a–f 的起音力度依次为 **48、36、76、80、112、80**。c 同时是断奏，实际播放时长为 **0.25 秒**。低声轨 bass/bass2 为 **64、96**。总时长 **3 秒**。计划包含 `hairpin_terminated` 诊断，指出 `swell` 在同声轨 mf 出现时提前结束；每条诊断有 feature、对象、来源位置和策略标识。

## 能力分开说明

| 内容 | 解析/验证 | 模型/区间 | 播放 | 本次渲染变化 |
| --- | --- | --- | --- | --- |
| 原有 12 种力度、6 种发音法 | 保持 1.1 | 类型化；区间/独立效果已实现 | 已接入真实计划生成 | 无 |
| 渐强/渐弱、连音、踏板、八度等原有关系 | 保持 1.1 | 端点和类型已解析 | 延续既有能力并修正力度区间 | 无 |
| words、印刷节拍器、歌词、和声、升降号等现有标记 | 保持 1.1 | 有显式方向类型/来源 | 不从任意文字猜测演奏效果；words 给出明确未演奏诊断 | 无 |
| 倚音、装饰音、导航/反复等完整后续领域 | 不扩大原有语法承诺 | 仅现有字段被保留/分类；未完成领域模型不得冒充已完成 | 不新增未实现效果 | 无 |
| MusicXML / MCSZ 等输入输出 | **没有新增转换器** | 为后续显式字段映射提供公共边界 | 未实现的转换不调用播放 | 无 |

`ResolvedScore` 目前是**演奏相关的共享语义视图**，不是已经取代整个作者文档的完整交换格式。原始 `Document` 继续持有元数据、小节、写法和未消费的版面字段；`lower_document` 不修改或丢弃调用方的原文档。后续渲染和格式转换必须逐域迁移并保留这些信息，不能把此阶段的视图误当成无损导出模型。当前标记中的一些纯显示值仍是经过 1.1 校验的注册 token，不能据此宣称所有词汇都已形成完整领域类型。

本次没有改 CSS、React、窗口、文件对话框或 MEI 透传。原渲染能力及其限制保持原样。表达术语不会直接作为外部 markup 交给渲染器或播放引擎。

## 验收与后续门槛

测试覆盖原有 conformance/roundtrip、所有现有力度与发音法词汇映射、具体谱表覆盖、有限区间恢复、同层冲突、相邻/重叠曲线、sfz/fp、时值与力度独立、两谱表实例，以及 10,000 音符的无累计时钟漂移检查。源文件顺序不能决定冲突结果。

公开 SFS 1.1 schema 未修改；新的内部模型目前是 Rust API，不声明已发布新的外部通用 AST schema。扩大语言词汇、转换 MusicXML/MCSZ、完整 renderer 适配和更多乐器资源仍分别需要字段设计、兼容性验证与独立测试。本次没有新增依赖、设备连接或 CI。
