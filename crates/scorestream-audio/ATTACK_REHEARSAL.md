# Explicit attack-velocity-only native rehearsal

This is a listening approximation, not realization of authored expression. The
only policy is `MidiAttackVelocityOnlyV1`, deliberately absent from defaults.
`prepare_attack_only_rehearsal` requires an opaque authenticated practice
`TechniquePlaybackPlan` and same-source sealed `LocalMidiMix`. Its immutable,
non-deserializable token binds the exact source digest and complete serialized
plan digest. It is not an arbitrary ignore-capabilities flag.

Native preparation still consumes the untouched notes, MIDI attack velocities,
onsets, durations, pitches, hold clock, consolidated ties and technique-channel
assignments. Only gain-envelope synthesis is omitted. The token records every
affected performed/written event and complete original point sequence. Counts
separately describe nonunit onset multipliers, constant nonunit shapes, varying
shapes, equal-time steps and positive-time changes; these categories can overlap
and are not a sum of unique notes. Musical provenance comes only from compiler
receipts, never guessed from a floating-point curve shape.

Malformed/nonfinite/negative/unsorted/out-of-note envelopes fail. A nonpositive
effective onset fails even if MIDI velocity is positive, both for all-zero curves
and zero-onset/later-positive curves. No silent note is dropped or resurrected.
The effective onset uses the final value among time-zero points; repeated-offset
steps remain in the exact omission record. No gain normalization or clipping of
the retained curve occurs.

Ordinary rendering still rejects practice/technique plans and nonunit envelopes.
The opt-in path requires matching source, plan, mixer, bank and technique receipts.
Same-key overlap, microtonal pitch, invalid velocity/timing, resource limits,
clipping checks and all other native failures remain independent and unchanged.
A successful gain-envelope approximation does not authorize a colliding MIDI key.

The render report carries the sealed omission token and an explicit warning that
the output is not faithful dynamics. Native tests use an authenticated synthetic
practice source, exact local TimGM6mb bank/preset and a chosen hold; no complete
score WAV is generated by these tests. Source and plan are unchanged after PCM.

Compiler `note_dynamics_receipts()` is copied into the token as typed provenance.
Exact rational `exact_note_on != integer_velocity` counts fractional NoteOn
residuals, separately from `relative_trajectory_applied` counts. Each receipt must
match its actual note velocity and full realized envelope. Affected notes without
such a compiler receipt are explicitly counted as lacking note-local provenance;
they are not mislabeled fractional NoteOn loss. The original and realized curves
remain present. The sample-bank output uses the unchanged integer MIDI velocity.

The local example requires the additional explicit argument
`midi_attack_velocity_only_v1` on `preflight-practice-attack-only` or
`render-practice-attack-only`; all prior source/practice/mixer/clock policies are
still required. Rendering additionally requires a successful native preflight,
actual bank/preset verification and a new output path. Ordinary `preflight-practice`
continues to reject these envelopes.
